# 不依赖Vercel的运行与部署

## 先本地操作
解压源码包，macOS可双击启动研究台.command；Windows运行启动研究台.bat。需已安装Python3.10+。若双击受系统限制，打开终端进入该文件夹执行：

```sh
python3 server/app.py
```

打开http://127.0.0.1:8765/。关闭终端会停止服务；不要直接双击HTML使用file://，浏览器会限制JSON和模块加载。若8765端口占用，可用macOS/Linux命令PORT=8766 python3 server/app.py并打开对应地址。

## 以后把HTML网站变成URL
网站由dist/index.html、CSS、JS、data.json及deliverables构成。上传整个dist文件夹到静态托管即可；无需重写产品、数据库或注册Vercel才可保留代码。

可选方式：
1. Netlify手动部署：在自己的账户中上传“静态网站部署包.zip”解压后的完整文件夹，获得netlify.app地址。
2. GitHub Pages：把静态包内容放到仓库发布目录，在Pages设置选分支/目录；获得github.io地址。若仓库有其它源码，按GitHub官方说明配置发布目录或Actions。
3. 自有服务器：将静态包解压到Nginx/其他Web服务器的站点目录，绑定域名并配置HTTPS。

配置文件vercel.json与netlify.toml适用于从完整源码根目录部署，输出目录为dist；“静态网站部署包”已经是输出内容，不再额外选dist子目录。平台账户注册、域名购买、付费方案及DNS修改不在本包中自动执行。

静态发布后在线AI仍未连接，/api状态不可用时保留离线证据模式。这不是部署失败。研究保存在浏览器，换网址前导出证据与台账两份备份，再到新网址恢复。

## 交付包范围
完整提交包含网站、源码、离线Git镜像、文档、测试记录、截图及96秒MP4；不含完整年报PDF、node_modules、账户密钥、本机浏览器数据或旧光储版本。原始材料通过直链追溯。打包脚本拒绝生成超过30MB的提交包。

公开URL尚待实际部署后填写，不能把本地localhost地址写成公开评审地址。

官方操作参考：[Netlify手动部署](https://docs.netlify.com/deploy/create-deploys/)、[GitHub Pages建站](https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site)。平台规则可能变化，以实际页面为准。
